# Airport Boutique Residence – заявки на прямое бронирование

Сайт апартаментов у аэропорта Кишинёва с формой заявки и админ-панелью (домашнее задание N1 «Сайт с заявками и админ-панелью»).

- **Сайт** (`/`): форма с полями «имя», «телефон», «даты заезда и выезда», «гостей» и «комментарий». Есть проверка в браузере и на сервере: пустая или неверная форма не отправляется и показывает ошибки. После отправки появляется подтверждение. Языки: RO / RU / UA / EN, вёрстка рассчитана на телефон.
- **Supabase**: таблица `cereri` с датой создания (`created_at`) и статусом (`noua` / `in_lucru` / `inchisa`), схема лежит в [`supabase/schema.sql`](supabase/schema.sql). RLS включён, публичного доступа нет, в базу пишут только серверные функции.
- **Админ-панель** (`/admin`): вход через Supabase Auth. Без входа API отвечает 401. Новые заявки показываются сверху, статус можно менять, есть фильтр по статусу.
- **Telegram**: каждая новая заявка сразу приходит в Telegram со всеми данными и временем по Кишинёву.
- **Ключи** хранятся только в переменных окружения Vercel: `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. В коде ключей нет, образец лежит в [`.env.example`](.env.example).

## Домашнее задание N2

- **CRM с этапами** (`/admin#crm`): «Новая заявка» → «Связались» → «Бронь подтверждена» → «Заселён» + «Отказ». Заявка с сайта сама попадает на первый этап с источником «Site», из Mini App — «Telegram», клиента можно добавить вручную («Manual»). Карточку можно перетащить в другую колонку или сменить этап в карточке. В карточке: имя, телефон, источник, дата создания, заметки и история перемещений с датами.
- **Распознавание документов через Claude API** (`/admin#cheltuieli`): фото чека или PDF счёта → Claude (`claude-opus-5-5`, структурированный JSON) → экран проверки с редактируемыми полями → запись в модуль «Расходы», оригинал хранится в приватном Supabase Storage и открывается по временной ссылке. Если файл не документ — понятное сообщение, ничего не сохраняется.
- **Telegram Mini App** (`/mini`): открывается кнопкой меню бота «Rezervare» на весь экран, здоровается по имени из Telegram. `initData` проверяется на сервере (HMAC-SHA256, срок 24 ч). Главное действие — заявка на бронирование — попадает в CRM с источником «Telegram» и именем из Telegram. В обычном браузере страница не показывает ничьих данных.
- **Генерация изображений** (`/admin#imagini`): из фото квартиры — «каталожное фото», квадратный пост или сторис через Google Gemini (Nano Banana). Генерация только на сервере, результат хранится в истории, лимит 5 изображений в день на пользователя (сообщение при превышении).
- **Ключи** только в Environment Variables на Vercel: дополнительно `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` (необязательно `IMAGINI_PE_ZI`). У провайдеров выставлены лимиты расходов. SQL для второго задания — [`supabase/tema2.sql`](supabase/tema2.sql).

Технологии: статические HTML/CSS/JS и Vercel Functions (Node 20+). Единственная зависимость — официальный `@anthropic-ai/sdk`.

```bash
npm test          # 34 теста (Supabase, Telegram, Claude и Gemini подменяются заглушками)
npm run dev       # http://localhost:3000 в режиме пробы, без внешних сервисов
```

Пошаговые инструкции (на румынском): [`GHID.md`](GHID.md) и [`GHID-TEMA2.md`](GHID-TEMA2.md).
